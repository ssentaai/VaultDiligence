# P3 · Oracle

P3  ·  Oracle & Price Feed Architecture  ·  Family C: Market, Oracle & Pricing Risk
Vault-type applicability note: Critical for VT-1 (DeFi Lending), VT-5 (Liquid Staking). Less critical for VT-3 (RWA) if off-chain pricing.
ID | Category | Criterion | What to Measure / How to Verify | Status | Institutional Standard | RF / Critical Conditions | Failure Case Anchor
3.1 | Source Redundancy | Multi-Source Oracle with Medianization | How many independent oracle sources? Are they medianized? What providers (Chainlink, Pyth, Chronicle, Redstone)? Are sources truly independent? | Gap with action | ≥3 truly independent sources (different data providers, not same source repackaged). Medianized output. No single source >50% weight. | RF08 · Single oracle source; medianization absent; sources correlated (same underlying data); custom oracle <6 months live | Venus $200M: single oracle manipulated. Mango $114M: single low-liquidity oracle manipulated for $114M profit.
3.2 | Manipulation Resistance | Oracle Manipulation Cost & TWAP Protection | How much capital is required to manipulate the price feed by 5%? Is there a TWAP (time-weighted average) fallback? Circuit breaker on deviation >X%? | Gap with action | Manipulation cost >$50M at any block. TWAP fallback activates on >2% single-block deviation. Circuit breaker halts protocol on >5% deviation. | Manipulatable for <$10M; no TWAP; no circuit breaker; deviation thresholds undefined | Cream Finance $130M: oracle price manipulation exploited low-liquidity pools to create false collateral value
3.3 | Freshness & Latency | Price Feed Update Frequency & Staleness Checks | How frequently does the oracle update? Is there an on-chain staleness check that reverts if the feed is stale? What is the max acceptable lag? | Gap with action | <5min for volatile assets; <1hr for stable assets. On-chain staleness check that reverts transaction if feed stale. Heartbeat monitoring. | Update >1hr for volatile assets; no staleness check in contract; contract accepts stale price without revert | Multiple protocols: stale prices during market volatility led to incorrect liquidation triggers and arbitrage opportunities
3.4 | Deviation Monitoring | Real-Time Deviation Alerting & Incident Response | Is oracle deviation monitored in real time? Who gets alerted? What is the response SLA? Can the protocol be paused if oracle is compromised? | Gap with action | <5min automated alerting on >1% deviation from market price. <15min incident response SLA. Multisig can pause oracle-dependent functions. | No deviation monitoring; manual monitoring only; no automated pause; incident response >1hr | Euler Finance: monitoring gaps meant exploit ran for minutes before detection — earlier alerting would have limited loss
3.5 | Bridge/Synthetic Risk | No Bridge-Dependent or Synthetic Price Feeds | Are any price feeds derived from bridge data or synthetic asset prices? Bridge exploits can corrupt these feeds with no warning. | Gap with action | No bridge-derived price feeds as primary sources. Wrapped asset prices independently verified against native asset. Bridge oracle not sole source. | Primary feed derived from bridge; bridge exploit could corrupt oracle; no independent verification of wrapped asset price | Wormhole $320M, Ronin $625M: bridge exploits would have corrupted any price feed derived from bridge-reported balances
3.6 | Oracle Upgrade-ability | Oracle Upgrade-ability — Hardcoded vs Governance-Updatable | Is the oracle hardcoded at deployment or can it be updated via governance? (1) Confirm whether oracle address is immutable in contract bytecode or points to upgradeable proxy. (2) If governance-updatable: what is the process, who proposes, what timelock applies. (3) If hardcoded: the oracle design choice made at deployment is permanent -- any flaw or mismatch is unresolvable without full contract redeployment. Matthew Graham precedent: Resolv hardcoded oracle created permanent exposure to infinite mint risk. Compare: Renzo TGE (spot vs NAV), Usual NAV governance update. Pattern: three consecutive Morpho oracle failures from hardcoded or misconfigured oracles. | Gap with action | Oracle is governance-updatable with timelock. Update process documented. No hardcoded oracle on collateral with known design tradeoffs. | RF38 | Renzo TGE: hardcoded spot oracle should have been NAV -- liquidations triggered. Usual: governance devalued asset via NAV update causing liquidation cascade. Resolv: hardcoded oracle created infinite mint exposure. Three failures, same root cause.
