# P7 · SmartCtrt

P7  ·  Smart Contract & Protocol Security  ·  Family A: Capital Safety & Legal Isolation
Vault-type applicability note: Applies universally. Timelock/multisig critical for all on-chain vaults. N/A for fully off-chain structures with no smart contract.

7.1 | Audit Quality | Tier-1 Smart Contract Audit — Recency & Scope | Which auditor? Trail of Bits, Certora, OpenZeppelin, Spearbit? When was the last audit? Were all findings resolved? Was there a re-audit on material changes?

AUDIT SCOPE MAPPING (from Resolv community analysis): For each audit, document what was explicitly OUT OF SCOPE. Were privileged roles excluded? Were off-chain signing services excluded? Were maximum limit validations flagged in any related contract? Zacodil precedent: December 2024 audit of Resolv had finding called 'Missing upper limit validation' -- different contract, not the minting role. Auditors treat privileged roles as out of scope by default. 

SKIN-IN-THE-GAME AUDITOR FLAG: Does any audit come from a firm with financial stake in findings? Sherlock = yes (auditors stake on findings, protocol pays if wrong). Standard firms = cash payment, no accountability post-deployment. Sherlock audit count is a separate positive signal from total audit count. | Gap with action | Tier-1 audit (Trail of Bits / Certora / Spearbit / OpenZeppelin) within 12 months. Zero unresolved criticals or highs. Re-audit on material upgrades. Report public. | RF02, RF13 · No external audit; unknown auditor; unresolved critical findings; >18 months since audit; scope excluded core vault logic | $3.8B lost to smart contract exploits in 2022 alone. 7.5 | MEV & Economic Attacks | MEV, Sandwich Attacks & Flash Loan Resistance | Has MEV analysis been done in the audit? Can strategy execution be front-run? 7.6 | Cross-Protocol Stack Contagion | For multi-protocol stacks: document failure propagation sequence from top to bottom layer. Identify whether a hub pause (Centrifuge), oracle failure, or liquidation event at one layer propagates to other layers. Confirm whether any coordinated circuit breaker exists.
7.7 | Withdrawal / Redemption Mechanics | ERC-7540 async redemption model: queue mechanism, max queue depth, cooldown periods. Instant withdrawal capability if any. Admin pause function — who holds it, what governance controls it.
7.8 | On-Chain / Off-Chain NAV Linkage | Oracle provider name, update frequency, validator count, staleness threshold. Protocol response to NAV anomaly (precedent: a tokenized CLO fund July 2025 NAV fell below $1.00 due to T+2 settlement timing). Is redemption paused during NAV anomaly?
7.9 | Yield and Fee Accounting | Are fee parameters embedded in smart contract logic or administered off-chain? Off-chain fee administration = governance and disclosure risk. Do fee changes require a governance vote with timelock?
7.10 | Guardrails and Circuit Breakers | Root contract emergency pause function. Per-transaction deposit caps. Redemption queue limits. Health factor thresholds in any lending integration. Are circuit breakers documented across the full stack?
7.11 | Governance and Permissioning | Multisig threshold and signer count. Timelock duration. Investor whitelisting control (Restriction Manager). Who controls token transfer permissions? Does any single entity hold unilateral control (e.g. 100% voting Management Shares)?
7.12 | Cross-Chain Architecture Risk | Hub-and-spoke: hub-level governance action or exploit propagates to all spokes simultaneously. Bridge dependencies: Wormhole, LayerZero, Axelar — each is a material failure vector. What does a hub pause mean for token holders on Avalanche, Base, Arbitrum?
7.13 | Privileged Role Documentation | Privileged Role Public Documentation & Transparency | Enumerate all privileged operational roles from contract bytecode (minting, burning, pausing, upgrading, parameter setting). For each role confirm: (1) publicly documented in litepaper/user docs/GitHub README, (2) security model stated, (3) key assignment process disclosed. Flag any role not mentioned publicly. Treat undocumented privileged roles as undisclosed risk regardless of audit coverage. | Gap with action | All privileged roles documented with security model. No undocumented role with unbounded authority. | RF30 | Resolv SERVICE_ROLE: unlimited minting authority, mentioned nowhere in public docs, missed by 18 audits.
7.14 | Issuance Mechanism Risk | Collateral Token Issuance Architecture & Supply-Side Risk | For synthetic or yield-bearing stablecoins accepted as collateral: identify issuance mechanism (on-chain autonomous vs off-chain signed two-step). Confirm: (1) on-chain maximum issuance bound per transaction exists in contract, (2) collateral-to-issuance ratio enforced at contract level not delegated off-chain, (3) implied NAV per token if supply doubled from fraudulent mint. Flag any collateral where supply can be inflated without corresponding backing. | Gap with action | On-chain issuance bounds enforced at contract level. No unbounded off-chain signing authority. | RF31 | Resolv: $200K in → $80M minted. $100M collateral now backs $180M supply. Implied NAV $0.56.
7.15 | Threat Model | Threat Model Documentation — Explicit Scope and Out-of-Scope Failure Modes | What failure modes does the protocol's risk architecture explicitly address? What is explicitly out of scope? (1) List all failure modes the design protects against (funding rate risk, liquidation risk, oracle manipulation, etc.). (2) List failure modes explicitly not covered (supply-side inflation, key compromise, governance attack, cross-protocol contagion). (3) Confirm whether the threat model has been independently reviewed. Jesus Rodriguez precedent: RLP dual-tranche architecture had a gap in its threat model. It was designed for collateral-side events. Supply-side inflation bypassed it entirely. The threat model gap was exploitable because it was never documented or stress-tested. | Gap with action | Threat model documented with explicit scope and out-of-scope. Supply-side, oracle failure, key compromise, and cross-protocol contagion addressed. | RF40 | Resolv dual-tranche: RLP designed for collateral-side losses. Supply-side inflation attack bypassed first-loss layer entirely. Threat model gap was undocumented and unreviewed.
7.16 | Off-Chain Infrastructure Security | Off-Chain Key Management, Cloud Security & Infrastructure Audit Scope | Assess the security posture of off-chain infrastructure that controls privileged protocol roles. Mandatory questions: (1) Where are privileged signing keys (SERVICE_ROLE, minting authority, admin keys) physically stored? Options: AWS KMS (highest risk), GCP KMS, Azure Key Vault, HSM (Hardware Security Module), MPC wallet (Fireblocks/Anchorage/Copper), hardware wallet (Ledger/Trezor). (2) Who has IAM/cloud access to the key management environment? Is access documented and audited? (3) Has off-chain infrastructure been explicitly included in any security review, penetration test, or audit scope? If yes: name the firm and date. If no: flag as gap. (4) What is the incident response plan if the key management environment is compromised? Is the plan documented, tested, and does it include a pause mechanism executable before damage propagates? (5) Are access logs for the key management environment monitored in real time? RESOLV PRECEDENT (March 2026): Attacker compromised AWS KMS environment. SERVICE_ROLE used to mint $80M unbacked USR. 18 smart contract audits did not cover off-chain infrastructure. $34M net loss. Audit scope must explicitly state whether off-chain signing services are in or out of scope. | Gap with action | Keys in HSM or MPC (not cloud KMS). Cloud access documented and audited. Off-chain infrastructure explicitly in security review scope. Incident response plan tested. Real-time access log monitoring. | RF41 · Keys in AWS/GCP/Azure KMS with no HSM; no documented access controls; off-chain infrastructure excluded from all audit scopes; no incident response plan for infrastructure compromise. Critical condition if keys are cloud-only with no additional controls. | Resolv March 2026: AWS KMS compromise. $34M net loss. Drift April 2026: social engineering of contributors + malicious VS Code repository. $285M loss. In both cases smart contract code was not the attack vector. Off-chain infrastructure and human access controls were.
