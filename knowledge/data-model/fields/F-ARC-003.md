# F-ARC-003

**Field ID**: F-ARC-003
**Category**: Archetype
**Sub-Category**: Framework Coverage Gap
**Field Name**: Framework Coverage — Seeded vs Unseeded Archetype
**What to Collect / Question to Answer**: For the archetype(s) the vault was classified as (F-ARC-002 — the UNION, for a multi-archetype vault), is the framework's routing for that archetype SEEDED or UNSEEDED? SEEDED = BOTH (a) its required-document set is defined in knowledge/framework/archetype/critical-documents.md (and its expected-set routing in expected-documents.md) AND (b) its risk fields exist (the F-STR-001..030 cluster for the Strategy value; the exposure look-through fields — e.g. F-COL / F-FIN structured-credit — for the Exposure value). UNSEEDED = the archetype is VALID in the dimension vocabulary (dimensions.md) but its document-set and/or risk-field CONTENT has not yet been built. Record, per matched archetype: SEEDED / PARTIALLY-SEEDED (some content built, some not — name WHICH) / UNSEEDED. Where unseeded or partial: state that part of the expected-document set and/or risk-field set is UNDEFINED for this vault pending a framework build — this is a FRAMEWORK gap (the framework has not defined this archetype's routing yet), explicitly DISTINCT from a VAULT gap (the vault is missing a document that IS defined). Flag the consequence so an undefined-because-unseeded set is NOT mistaken for the vault being complete.
**Data Type**: Structured (per matched archetype: coverage state {seeded | partially-seeded [built vs not] | unseeded}; the undefined portion of the expected-document / risk-field routing; framework-gap-vs-vault-gap label; as-of-date)
**Vault Types**: ALL — every classified archetype is checked for coverage. In practice the CLO-fund / delegated-offchain-IM archetype is SEEDED (critical-documents.md); most other archetypes reuse the routing MECHANIC but their per-archetype CONTENT is a documented follow-on, so they classify partially-seeded / unseeded until built.
**Collection Tier**: T2
**Pillar(s)**: Archetype-level (propose; sibling to F-ARC-001 / F-ARC-002 — operator confirms)
**Primary Source**: The framework's OWN state — knowledge/framework/archetype/critical-documents.md (which archetypes' required-sets are seeded), expected-documents.md (which routing content exists), and the field registry (whether the archetype's F-STR / exposure risk fields exist). This is an internal-framework check, NOT a vault-disclosure check.
**Fallback Source**: The DECISIONS log and MASTER-PLAN for whether an archetype's build is planned or pending; the strategy-risk-fields agent backlog (staking, options-premium, arbitrage, carry/curve remain unbuilt per the F-STR ratification — worked examples of unseeded strategy risk-fields)
**Evidence Pathway**: Framework-self-evidenced: for the matched archetype's Exposure and Strategy values, check whether critical-documents.md seeds a required-set and whether the corresponding risk fields exist, then classify seeded / partially-seeded / unseeded and record the undefined portion with an as-of-date. Directly verifiable against the tree.
**Institutional Standard**: For each archetype a vault is classified as, the framework states whether it has SEEDED that archetype's document-set and risk-fields — so an UNDEFINED (unseeded) portion of the expected set is visible as a FRAMEWORK gap (the framework's own incompleteness) and is not silently counted as the vault being complete. The remediation for an unseeded archetype is a framework BUILD (define the archetype's routing), distinct from the vault-DDQ remediation of a missing-but-defined document. A factual coverage statement, never a score or quality verdict.
**Status**: Gap with action
**If Not Found — Gap Action**: Coverage state recorded per matched archetype, the undefined portion named, with an as-of-date: E. Coverage assessed but the undefined portion not fully enumerated: E(P). UNSEEDED or PARTIALLY-SEEDED = a FRAMEWORK gap: the action is a framework build (seed the archetype's required-document set in critical-documents.md and its risk fields), NOT a vault DDQ — record it so the vault's document audit is not read as complete when part of its expected set is merely undefined. This is explicitly distinct from F-DOC-001 / RF48 VAULT gaps (a defined document that is gated / absent). SEEDED = no framework gap; the document audit proceeds against the seeded set.
**Source / Precedent**: knowledge/framework/archetype/critical-documents.md (the seeded CLO-fund set plus its "other archetypes generalize the mechanic; content is a documented follow-on" statement — the direct basis for seeded-vs-unseeded); expected-documents.md ("the MECHANIC generalizes; per-archetype CONTENT is filled in per assessment"); the F-STR ratification (a framework decision of 2026-07-09: staking / options-premium / arbitrage / carry-curve strategies remain unbuilt — the worked unseeded cases); an internal analysis. The framework-gap-vs-vault-gap distinction follows the evidence-standards principle that a gap must state its precise action — and here the action differs (framework build vs vault DDQ).
**Cross-references**: F-ARC-002 (the vault's fit — this field is its framework-coverage counterpart); knowledge/framework/archetype/critical-documents.md + expected-documents.md (the seeded document routing this checks); F-DOC-001 (whose expected-set is UNDEFINED where this field reads unseeded — the consumer that must not mistake undefined for complete); RF48 (which fires on a VAULT document gap, distinct from this FRAMEWORK gap); the F-STR-001..030 cluster (seeded strategy risk-fields; the unbuilt strategies are the unseeded cases).
