# F-DOC-001

**Field ID**: F-DOC-001
**Category**: Project Gate
**Sub-Category**: Document Availability
**Field Name**: Expected-Document Availability Matrix
**What to Collect / Question to Answer**: Enumerate the documents EXPECTED for this vault's archetype and record each one's availability. The expected SET is derived from the archetype tuple — (Exposure, Management, Strategy) per knowledge/framework/archetype/dimensions.md — using the routing in knowledge/framework/archetype/expected-documents.md (ONCHAIN-base always; OFFCHAIN-set when Management = delegated-offchain-IM or an off-chain-custodied exposure; Exposure addenda e.g. structured-credit›CLO; Strategy addenda via the F-STR cluster). For EACH expected document record: (1) document name / type; (2) LAYER — onchain or offchain (an offchain-layer absence is the sharper risk); (3) whether it is expected-for-this-archetype and which tuple element requires it; (4) the associated party by F-ROL role ID, and flag whether that party is a yield-critical party per F-STD-001 (IM / sub-advisory agreements, audited financials, and asset schedules belong to yield-critical parties — F-STD); (5) the AVAILABILITY STATE (spec/document-availability-states.md: OBTAINED / GATED-CONFIRMED / EXPECTED-UNCONFIRMED / ABSENT-CONFIRMED / N/A); (6) the as-of-date. This is the per-vault answer against the archetype template — the parallel, for documents, of F-PRJ-003 (roles).
**Data Type**: Structured (table: document/type -> layer {onchain|offchain} -> expected-because {tuple element} -> associated party {F-ROL id; F-STD yield-critical flag} -> availability_state {enum} -> as-of-date)
**Vault Types**: ALL (the expected set routes off the archetype tuple; N/A only where the archetype has no expected-document set — e.g. a fully immutable crypto-native protocol vault with no offchain layer — state why)
**Collection Tier**: T2
**Pillar(s)**: P0 (Project Gate — sibling to F-PRJ-003 All Critical Roles Named)
**Primary Source**: The vault's own document set (onchain: contracts, tokenization terms, audits, oracle / NAV; offchain: OM / PPM, IM / sub-advisory agreement, audited financials, asset schedule, custody agreement), located per the archetype expected-set routing
**Fallback Source**: Operator / party DDQ for gated or unconfirmed documents; the associated F-ROL / F-STD party for offchain fund docs; F-ENT-075 (executed service-provider agreements on file) for the service-provider slice
**Evidence Pathway**: Third-party-evidenced: derive the expected set from the archetype tuple, then for each document establish its availability state — OBTAINED where in hand, GATED-CONFIRMED where confirmed to exist but access-firewalled (a DDQ item, not a finding), EXPECTED-UNCONFIRMED where standard for the archetype but existence cannot be confirmed, ABSENT-CONFIRMED where confirmed not to exist, N/A where the archetype does not require it. Record each with its as-of-date.
**Institutional Standard**: The vault's expected-document set is enumerated from its archetype and each document's availability is recorded and dated, split onchain / offchain and mapped to the party that owns it — so an offchain document that is expected-but-absent (the sharpest absence, and usually a yield-critical party's fund document) is visible rather than hidden behind a generic "gap", and a gated-but-existing document is distinguished from one that does not exist.
**Status**: Gap with action
**If Not Found — Gap Action**: Expected set enumerated from the archetype and every document dated with an availability state: E. Set enumerated but some states unconfirmed this session: E(P). A GATED-CONFIRMED document (exists, firewalled): route a DDQ to the associated party — neutral, not a finding. A document EXPECTED-UNCONFIRMED or ABSENT-CONFIRMED: surfaces via RF48 as a critical condition (stronger for an offchain document of a yield-critical party); if standard for the archetype and confirmed absent, the operator must create / publish it (G3). The absence PATTERN (count of EXPECTED-UNCONFIRMED + ABSENT-CONFIRMED) is recorded as a factual count, never scored.
**Source / Precedent**: an internal analysis (2026-07-08): the framework recorded documents found but had no expected-document SET per archetype, no epistemic-middle availability state, and the gated-vs-absent split died at the RF trigger. Seed content: knowledge/framework/archetype/expected-documents.md (routing + the CLO-fund / a tokenized CLO fund set); F-ENT-075 (executed service-provider agreements on file); the an ODD source ODD "Document Set" (an operational due-diligence checklist). Availability enum: spec/document-availability-states.md.
