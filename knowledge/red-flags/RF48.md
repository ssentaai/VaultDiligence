# RF48

RF48 | MATERIAL | P0 | 0.4 Expected-Document Availability | An expected document for the vault's archetype is EXPECTED-UNCONFIRMED (standard for the archetype but existence cannot be confirmed) or ABSENT-CONFIRMED (confirmed not to exist) in the F-DOC-001 availability matrix — a stronger condition for an OFFCHAIN-layer document owned by a yield-critical party (F-STD). A GATED-CONFIRMED document (exists but access-firewalled) does NOT trigger; it is a neutral DDQ item. Absence-pattern aggregate: the factual COUNT of expected documents in EXPECTED-UNCONFIRMED / ABSENT-CONFIRMED (many missing = a stronger signal), recorded as a count, never a score. Surfaces as a critical condition; never auto-blocks (anchor #3), never scores (anchor #4). | F-DOC-001 | Any F-DOC-001 row with availability_state in {EXPECTED-UNCONFIRMED, ABSENT-CONFIRMED} = TRIGGER; availability_state in {OBTAINED, GATED-CONFIRMED, N/A} = NO TRIGGER (GATED-CONFIRMED routes to a DDQ, not the flag); record the count of triggering rows, and the subset that are OFFCHAIN + yield-critical-party, as the absence-pattern signal | For GATED-CONFIRMED: obtain via the access route (DDQ to the associated F-ROL / F-STD party). For EXPECTED-UNCONFIRMED: confirm existence with the associated party and resolve to OBTAINED / GATED-CONFIRMED / ABSENT-CONFIRMED. For ABSENT-CONFIRMED and standard-for-archetype: the operator must create and publish it. | ALL (where the archetype has an expected-document set; N/A for a crypto-native protocol-native vault with no offchain layer) |
